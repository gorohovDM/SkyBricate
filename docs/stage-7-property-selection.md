# Этап 7: выбор применяемых свойств

Реализована чистая синхронная функция `selectProperties` в `scripts/property-selection.js`. После готовности модуля она также доступна как `game.modules.get('skybricate').api.selectProperties`. Функция не читает Foundry, настройки мира или хранилище, не меняет входные данные и не применяет свойства к Item.

## Вход

```js
selectProperties({
  componentIds: ['A', 'B'],
  system: { properties, components, specialComponents },
  recipeRules: {
    limitByCheck: true,
    outcomeLimits: { success: 2, failure: 0 },
    prioritySpecial: false,
    propertyOrder: ['property-X']
  },
  outcome: 'success'
});
```

`system` — явно переданный snapshot одной системы: каталог `properties` и карты обычных/особых назначений `componentId -> propertyId[]` из схемы 4. Полный объект системы разрешён, но `system.rules`, категории, знания и любые настройки отображения не используются. Метаданные записей каталога алгоритму не нужны. Вызывающий код выбирает систему; межсистемных поисков нет.

`componentIds` представляет состав до расхода компонентов. Повторы одного ID допускаются и схлопываются; количества экземпляров не увеличивают число источников. ID без сохранённых назначений допустим и ничего не добавляет: карты назначений не являются каталогом компонентов Fabricate.

`recipeRules` необязателен; значения по умолчанию: `limitByCheck=false`, `outcomeLimits={}`, `prioritySpecial=false`, `propertyOrder=[]`. Это явно переданные правила конкретного рецепта, отдельные от исторических правил системы. Их интерфейс и хранение относятся к этапу 8. Поле `successLimit` не поддерживается: для каждого исхода используется только `outcomeLimits[outcome]`.

Включённый лимит требует безопасного непустого строкового `outcome` и собственного ключа в `outcomeLimits`, даже при пустом составе или лимите 0. Отсутствующий/неизвестный исход или отсутствующее количество вызывает явную ошибку входных данных — решение подтверждено пользователем. Названия исходов задаёт вызывающая сторона через карту, штатные исходы Fabricate будут сопоставлены адаптером этапа 9. При выключенном лимите исход не используется.

Лимиты — неотрицательные безопасные целые числа; 0 допустим. Проверяются plain records, безопасные ID по общему контракту, ссылки на каталог, повторы ссылок, конфликт типов одной пары компонент/свойство и неизвестные поля правил/параметров. Повреждённые назначения отклоняются также у неучаствующих компонентов. Ошибки выбрасываются как `Error`, без исправления данных или частичного результата.

## Выбор и результат

Обычное совпадение требует двух различных componentId. При выключенном приоритете обычные и особые назначения вместе участвуют в совпадении. При включённом приоритете особый кандидат не требует совпадения, идёт первым и исключает свой propertyId из обычного пути до ограничения количества. Для остальных свойств нужны два обычных источника.

В каждой группе сначала идут свойства из `propertyOrder` в указанном порядке, затем остальные по ID (сравнение строк `<`/`>`, независимо от локали). Порядок мастера не перемещает обычное свойство перед особыми. Общий лимит обрезает объединённую последовательность различных propertyId; выключенная зависимость выбирает всех подходящих кандидатов.

Результат — новый массив, например:

```js
[{ propertyId: 'X', selectionType: 'special', sources: [
  { componentId: 'A', assignmentType: 'special' }
] }]
```

`selectionType` — путь выбора: `special` или `matched`. `assignmentType` — тип исходного назначения: `ordinary` или `special`. В пути `matched` при выключенном приоритете источники могут иметь оба типа. Особый путь сохраняет только особые источники, даже если у других участвующих компонентов есть обычное назначение того же propertyId. Источники упорядочены по componentId. Повторов свойств и источников нет; изменение возвращённого результата не меняет входные карты.

## Проверки и границы

Регрессии `tests/selection-regressions.mjs` подключены к общему suite: совпадение разных ID, повторные экземпляры, смешанные типы, приоритет/порядок групп, общий лимит/0/без лимита, явные ошибки исходов, валидация, происхождение, детерминизм и отсутствие мутации. API и включение нового runtime-файла проверяются общим suite и сборкой.

Реализован только этап 7. Настройки и хранение правил рецепта (8), чтение штатного броска и состава/применение к результату (9), автооткрытие знаний (10) не подключены. Результат выбора ещё не является фактом применения или раскрытия. Ручной запуск Foundry не выполнялся; для чистой функции он не требуется.
