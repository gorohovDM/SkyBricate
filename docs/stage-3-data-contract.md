## Схема 1

Собственное скрытое world setting `skybricate.data` регистрируется при `init`, `type: Object`, `config: false`. Значение по умолчанию:

```json
{"schemaVersion":1,"properties":{},"systems":{}}
```

`properties` — общий словарь `propertyId -> {name, description}`. ID создаётся `crypto.randomUUID()`, не зависит от имени. Название непустое; описание — строка, по умолчанию пустая. Искусственного ограничения количества записей нет.

`systems[craftingSystemId]`:

```json
{
  "categories": {"Fabricate category key": ["propertyId"]},
  "components": {"Fabricate componentId": ["propertyId"]},
  "rules": {
    "limitByCheck": false,
    "successLimit": 0,
    "outcomeLimits": {},
    "prioritySpecial": false,
    "propertyOrder": []
  }
}
```

`categories` хранит наследуемые назначения; `components` — только особые свойства. Принадлежность компонента категории остаётся в Fabricate. Один propertyId может быть назначен нескольким категориям/компонентам. Категории Fabricate — строковые ключи, не UUID. `renameCategory` явно переносит назначения; автоматическая синхронизация с редактором Fabricate отложена.

`outcomeLimits` — словарь стабильных outcomeId, не видимых названий. `successLimit` — лимит успешного simple check. Лимиты — неотрицательные целые числа, точно представимые JS. `propertyOrder` — упорядоченный список уникальных propertyId (может быть неполным). Это сохранённая конфигурация: алгоритм выбора и порядок оставшихся кандидатов относятся к этапу 7. Наличие этих полей пока не меняет крафт. Ссылки на native essence/эффекты/макросы пока отсутствуют: их точный контракт определяется будущим адаптером.

## Внутренний service

После успешного compatibility/readiness guard `game.modules.get("skybricate").api.data` содержит `DataStore`. Это внутренняя точка для будущих редакторов, не обещание стабильного API внешним модулям.

- `getSnapshot()` читает актуальное локально доступное setting и возвращает независимую копию.
- `createProperty`, `updateProperty`, `deleteProperty` управляют каталогом. Переименование не меняет ID; удаление чистит все ссылки и порядок во всех системах.
- `ensureSystem`, `deleteSystem`, `setCategoryProperties`, `renameCategory`, `deleteCategory`, `setComponentProperties`, `deleteComponent`, `configureRules` управляют изолированными настройками систем. Assign заменяет полный список; patch правил заменяет переданные поля (в том числе весь outcomeLimits). Отсутствующий system создаётся только ensure/assign/configure. Отсутствующие удаления category/component/system допустимы. Переименование в существующую категорию — ошибка, одинаковые старый/новый ключи допустимы.
- Каждая запись повторно проверяет `game.user.isGM` при исполнении операции. Чтение не является защитой секретных данных от консоли игрока; `config: false` лишь скрывает настройку из обычного меню.

Валидация отклоняет неизвестные поля/версии схемы, повреждённые значения, висячие/повторные ссылки, неверные лимиты и опасные ключи `__proto__`, `prototype`, `constructor`. Чтение ничего не исправляет и не сохраняет. Автомиграций нет. Ошибки чтения/валидации/сохранения передаются вызывающему коду; успех возвращается после `settings.set`. Локального изменяемого кеша нет.

Операции одного экземпляра выполняются последовательно, перечитывают setting перед изменением и продолжают очередь после ошибки. Аргументы-массивы и patch копируются при вызове. Между клиентами GM блокировки нет: действует последнее сохранение; это согласованное ограничение. Копии не защищают от стороннего кода, напрямую пишущего в `game.settings`.
