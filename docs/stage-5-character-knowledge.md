# Этап 5: знания персонажей и ручное управление GM

Реализован только этап 5. Интерфейс игрока, алгоритм применения, подключение крафта и автоматическое открытие относятся к последующим этапам.

## Контракт

В «Настройки игры» → «Настроить параметры» → SkyBricate доступно отдельное окно «Открыть знания персонажей». GM выбирает Actor мира, сохранённую систему крафта и компонент. Список показывает назначенные свойства, их состояние «Известно»/«Неизвестно» и действие «Раскрыть»/«Скрыть». Каждое действие сохраняется сразу. Скрытые особые назначения не показываются, их знания сохраняются. Используются Actor мира любых типов, без зависимости от system.type; synthetic token Actors не входят в объём.

API после готовности: `game.modules.get('skybricate').api.openKnowledge()`; сервис записи: `api.data.setPropertyKnowledge(actorId, craftingSystemId, componentId, propertyId, known, { canWrite })`. Снимок: `api.data.getSnapshot().knowledge[actorId]?.[craftingSystemId]?.[componentId]`, массив известных propertyId. Отсутствие ID означает неизвестное свойство. Метод записи возвращает Promise; успешное завершение означает успешную запись world setting. Читать состояние можно из нового экземпляра DataStore; изменяемый кеш отсутствует.

Схема 4 добавляет top-level `knowledge`, сохраняя системы схемы 3. Корректные схемы 2 и 3 читаются без записи: схема 2 получает пустые specialComponents, обе получают пустые knowledge. Миграция сохраняется только вместе с успешной операцией. Невалидные, неизвестные и будущие данные не нормализуются и не сбрасываются. Схема 1 сохраняет прежний явно подтверждаемый сброс тестовых данных.

Подтверждённые правила:

- Знание изолировано по actorId, craftingSystemId, componentId и propertyId; свойство другого компонента не раскрывается.
- Переименование со стабильными ID и перевод ordinary ↔ special в одном сохранении сохраняют знание по объединению назначений обоих типов.
- Новое назначение неизвестно. Удаление назначения очищает знание; повторное добавление не восстанавливает его.
- Выключение показа особых свойств сохраняет особые назначения и знания.

После любого изменения SkyBricate знания очищаются по оставшимся назначениям в той же транзакции `skybricate.data`. Это покрывает удаление свойства, компонента, системы и сверку назначений; ошибка сохранения сохраняет исходные знания и назначения. Сверка компонентов использует проверенный полный persisted corpus Fabricate 1.9.10. При полном успешном чтении сверка также убирает знания отсутствующих систем, сохраняя их прежние каталоги/назначения по контракту этапа 4. Ошибка/неизвестный формат corpus запрещает запись и очистку. Удаления Fabricate подхватываются существующими адаптерами и при открытии/обновлении редакторов; отдельного наблюдателя за удалением систем нет. Если удалить и вернуть тот же ID до сверки, промежуточное удаление не наблюдается.

GM проверяется сервисом при выполнении очереди и интерфейсом; любой GM вправе менять знания, activeGM не требуется. Перед queued write повторно проверяются Actor мира, сохранённая система, компонент, свойство, назначение и callback контекста окна. Закрытое/отсоединённое окно и потеря прав запрещают ещё не начатую запись. Уже начатый settings.set отменить нельзя, но закрытое окно не обновляется после завершения. Пока действие ожидает завершения, навигация и повторные действия блокируются; сообщение об успехе появляется только после записи. Ошибка оставляет возможность повтора. Несколько клиентов сохраняют существующий last-write-wins; распределённых блокировок нет.

## Проверки и ограничения

Автоматические регрессии покрывают persisted roundtrip, изоляцию ключей, GM и повторную проверку queued контекста, миграцию 2/3, повреждённые данные, очистку/смену типа/скрытые назначения, отказ сохранения и повтор, DOM без HTML-инъекций, навигацию/закрытие и ApplicationV2/settings/API. RU/EN имеют одинаковый набор ключей. Общая команда: `node --test tests/regression.test.mjs`.

Поставка: `node tools/build.mjs`; новые runtime-файлы включены в строгий allowlist, архив проверяется на воспроизводимость. Stock probes: `node --conditions=browser tools/check-fabricate-editor.mjs` и `node --conditions=browser tools/check-fabricate-assignments.mjs`. Результат проверки реализации: регрессии 75/75 PASS, сборка PASS (14 runtime-файлов), оба stock probes PASS. Точный SHA публикуется в передаче исполнителя.

Ручной запуск Foundry исключён. Настоящий мир, перезапуск, реальные Actor Collections, темы и визуальный layout в Foundry не проверялись. Foundry 13–14 и обычный Fabricate 1.9.10 остаются целевым контрактом.

Оценка полного цикла: 6 / 9,5 / 14 млн токенов (оптимистично / основной прогноз / запас). Фактический расход не измерен.
