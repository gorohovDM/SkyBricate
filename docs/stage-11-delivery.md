## Установка

1. Сохраните резервную копию мира и остановите сервер Foundry.
2. Соберите модуль или возьмите проверенный локальный `dist/skybricate.zip`. Распакуйте содержимое в `Data/modules/skybricate`: файл `module.json` должен лежать непосредственно в этой папке, рядом с `scripts`, `styles`, `lang`.
3. Установите обычный Fabricate **1.9.10**. При наличии прежнего экспериментального патча переустановите официальный Fabricate той же версии с сохранением данных мира.
4. Запустите Foundry, откройте нужный мир и включите Fabricate и SkyBricate. Устанавливаемый модуль не требует Node.js или npm-зависимостей.
5. GM открывает справочник в «Теги и категории» менеджера Fabricate, назначения и знания — кнопками SkyBricate/настройками модуля, правила — из строки сохранённого рецепта. Игрок использует вкладку «Свойства компонентов» с выбранным персонажем. Подробные правила описаны в README и контрактах этапов.

Установка по URL манифеста требует отдельно опубликованного GitHub Release; данная поставка подтверждает только локальные файлы.

## Ограничения

- Целевые Foundry VTT 13–14 указаны без `verified`. Настоящий мир, перезапуск Foundry, темы, узкие окна и реальные диалоги не проверялись. Автоматические stock probes используют исходники Fabricate и тестовую среду; они не заменяют проверку настоящего мира.
- Подтверждена только Fabricate 1.9.10 с указанным SHA. Модуль использует внутренние engine-контракты; совместимость иных версий не заявляется.
- Скрытые сведения защищены от отображения и поиска в интерфейсе, но world setting доступен клиентскому коду; серверной секретности каталога нет.
- Хранилища Fabricate и SkyBricate не являются атомарной транзакцией; между клиентами действует последняя запись. Неизвестные/повреждённые схемы и старые craft runs без нужного provenance отклоняются; ограничения миграций и сверки описаны в README.
- Автораскрытие требует activeGM. Сбой между одноразовой отметкой Item и записью знаний требует ручного раскрытия GM; автоматическое повторение крафта не выполняется. Применение и атрибуция используют консервативный аудит реальных изменений, со всеми ограничениями этапов 9б и 10.
- Незакоммиченные пользовательские правки документации и локальный `docs/current-plan.md` сохранены отдельно от этого изменения. На них устанавливаемый runtime и воспроизведение проверок не опираются.
