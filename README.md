# SkyBricate
Дополнение для Fabricate: скрытые обычные и особые свойства компонентов и постепенное открытие знаний персонажами. Модуль использует штатные проверки, перенос эффектов и создание результатов Fabricate; поддерживает немедленный, отложенный и многошаговый крафт и автоматическое раскрытие реально применившихся свойств.

Текущая версия 0.2.0 содержит справочник и назначения свойств отдельно для каждой системы крафта, знания персонажей, правила рецептов, применение свойств к результатам и автоматическое раскрытие знаний. В мастерском редакторе Fabricate выберите систему, откройте «Теги и категории» → «Свойства SkyBricate». Вкладка оформлена по аналогии с соседними справочниками: описание, поля названия и описания с кнопкой «Добавить», количество свойств и карточки со стандартной иконкой тега, названием, редактированием и удалением. Поиск пока отключён с пояснением; счётчик показывает число связанных сохранённых компонентов. Выбора иконок нет. Вкладка доступна мастеру при любом режиме выбранной системы; применение при штатном крафте описано ниже.

Переименование сохраняет ID и связи. Удаление требует отдельного подтверждения и очищает назначения категориям, компонентам и порядок правил только в выбранной системе. Вкладка показывает ожидание сохранения, подтверждает успех после записи и сохраняет ввод при ошибке для повторной попытки. Панели справочника в настройках крафта больше нет.

Данные сохраняются в собственном скрытом world setting, схема 7. Изменять их может мастер. Каталоги, назначения категориям/компонентам и правила изолированы по системе. Старые тестовые данные схемы 1 с общим справочником не мигрируются: вкладка предлагает явный сброс с отдельным подтверждением удаления всех старых свойств, назначений и правил SkyBricate в мире. Сбрасывается только skybricate.data; данные Fabricate не меняются. Повреждённые, неизвестные и будущие схемы отклоняются без перезаписи и не получают кнопку сброса.

Кнопка «Привязки свойств» в панели действий менеджера ГМа Fabricate открывает отдельное окно назначений SkyBricate. Она доступна в разделах с общей панелью действий Fabricate; систему и компонент выбирают в самом редакторе. Редактор назначений также открывается отдельно: «Настройки игры» → «Настроить параметры» → SkyBricate → «Открыть редактор назначений». Он доступен мастеру и работает с обычным Fabricate 1.9.10. Выберите сохранённую систему крафта и компонент; подписи включают ID для различения одинаковых имён. Назначения представлены зонами «Обычное свойство» и «Особое свойство». Справа от заголовка каждой зоны кнопка «Добавить» создаёт строку с выпадающим списком свойств текущей системы и корзиной. Уже выбранное свойство исключается из остальных списков обеих зон, включая скрытые особые назначения; пустые строки не записываются. «Снять все» очищает видимые зоны, «Сохранить свойства» записывает назначения отдельно от штатных полей Fabricate. Назначения категориям не подмешиваются. При пустом справочнике показана подсказка, где создать свойства; пустые системы и компоненты также имеют пояснения.

Ошибка сохранения оставляет выбор для повторной попытки. При смене системы или компонента, перечитывании, сверке и закрытии несохранённый выбор сбрасывается; предупреждение видно заранее. Переименование компонента и смена категории сохраняют назначения по ID. Для чтения изменений другого мастера используйте перечитывание. Несколько окон имеют независимый выбор и общую очередь записи клиента. При записи разных клиентов действует последняя запись; межклиентской блокировки нет. Схема 2 строго проверяется и читается как обычные назначения без изменения исходных данных; первая успешная запись SkyBricate, включая сверку при открытии окна, сохраняет схему 3. Отказ записи сохраняет исходную схему. API мастера: game.modules.get('skybricate').api.openAssignments().

При открытии окна, перечитывании и нажатии «Сверить сохранённые назначения» SkyBricate сравнивает назначения с полным сохранённым корпусом систем и компонентов Fabricate. Удалённые компоненты очищаются только в исходной системе; мгновенная очистка при удалении не выполняется. После удаления откройте окно или выполните сверку. Система с явным пустым списком компонентов допускает очистку, а отсутствующая система, ошибка чтения и повреждённый корпус не считаются пустым списком. Отмена или отказ сохранения удаления в Fabricate не очищают назначения. При ошибке сверки сохранённые данные остаются для повторной попытки. Два хранилища не образуют атомарную транзакцию.

Настройка SkyBricate «Показывать особые свойства» действует на весь мир (world) и по умолчанию выключена. Она скрывает особую зону, сохраняя назначения и их тип. При переключении открытые окна перечитывают особые строки из сохранённых данных; несохранённые особые строки сбрасываются, обычный ввод сохраняется. Сохранение и очистка при скрытой зоне сохраняют актуальные особые связи из очереди записи. Настройка не меняет prioritySpecial и будущий алгоритм. Один propertyId может быть обычным у одного компонента и особым у другого; у одного компонента два типа одновременно запрещены. Интерфейс строк из описания 5а включён в этап 4а по запросу пользователя. Контракт и проверки: [этап 4а](docs/stage-4a-special-assignments.md).

В настройках SkyBricate мастер может открыть отдельное окно «Знания персонажей». Выберите персонажа мира (Actor любого типа), систему крафта и компонент: список назначенных свойств показывает «Известно»/«Неизвестно», кнопки «Раскрыть»/«Скрыть» сохраняют изменение сразу. Знания изолированы по персонажу, системе и компоненту. Переименование и смена типа назначения сохраняют знание; удаление назначения сбрасывает его, повторное добавление делает неизвестным. Скрытие особой зоны сохраняет знания. Изменять их может любой GM; ошибки сохранения позволяют повтор. Схемы 2/3 читаются без потерь и обновляются до схемы 4 только после успешной записи. Контракт и проверки: [этап 5](docs/stage-5-character-knowledge.md).

В окне игрока Fabricate доступна вкладка «Свойства компонентов». Выберите персонажа в общей верхней панели Fabricate и сохранённую систему крафта внутри вкладки: у каждого компонента видны известные названия и описания, остальные назначения показаны одинаковыми неизвестными слотами. Поиск учитывает названия компонентов и только известные названия/описания свойств. Смена персонажа сбрасывает панель; смена системы сбрасывает поиск. Кнопка «Перечитать», сохранение данных и переключение показа особых свойств обновляют открытый список. Эта вкладка только читает данные. При выключенном показе особые назначения и знания сохраняются. Скрытые названия, описания и ID свойств не попадают в DOM и поиск; общее world setting остаётся доступным клиентскому коду, поэтому это скрытие в интерфейсе, а не серверная защита каталога. Контракт и проверки: [этап 6](docs/stage-6-player-knowledge.md).

Проверка player provider на настоящем stock registry и Svelte PlayerExtensionHost: node --conditions=browser tools/check-fabricate-player.mjs <путь-к-Fabricate>. Полный набор из пяти stock-проверок и результаты итоговой проверки перечислены в [отчёте поставки](docs/stage-11-delivery.md).

Алгоритм этапа 7 выбирает свойства по переданному составу компонентов и правилам конкретного рецепта: совпадение требует разных компонентов, особый приоритет включается отдельно, порядок мастера и общий лимит по исходу проверки определяют результат. Выбор сохраняет тип и источники назначений, не зависит от знаний и видимости особого раздела. Чистая функция доступна через API selectProperties; контракт и примеры: [этап 7](docs/stage-7-property-selection.md).

Этапы 9а–9в подключают выбор и применение свойств к штатному крафту, включая отложенные и многошаговые рецепты. Этап 10 автоматически открывает знания по реально применившимся свойствам; итоговая проверка и локальная поставка выполнены в [этапе 11](docs/stage-11-delivery.md).

После успешной выдачи результата SkyBricate открывает персонажу только свойства, которые действительно изменили Item через macro или перенесённый эффект, и только у расходовавшихся компонентов из сохранённого аудита. Особый путь раскрывает только особые источники; лимит, отсутствие изменений, перезапись, неуспешная выдача, отмена и ожидание времени знаний не дают. Автоматически пишет activeGM, включая крафт игрока; любой GM сохраняет ручное управление. Сохранённые новые awards без activeGM обрабатываются при его появлении или перезагрузке клиента. Одноразовая отметка на Item защищает ручное скрытие и повторное назначение от повторной доставки старого award. При сбое между отметкой и записью знаний требуется ручное раскрытие GM; повтор крафта не выполняется. Контракт, границы доставки и проверки: [этап 10](docs/stage-10-craft-discovery.md).

В библиотеке рецептов GM кнопка с ползунками рядом с карандашом открывает «Правила рецепта SkyBricate» для конкретного сохранённого рецепта. GM выбирает разрешённые свойства каталога системы, задаёт их порядок, приоритет особых и максимальное количество по штатным исходам проверки. Пустой сохранённый список запрещает все свойства; до первого сохранения сохраняется поведение этапа 7. Правила сохраняются отдельной кнопкой, штатный черновик и сохранение Fabricate остаются самостоятельными. Изменения свойств и знаний совместимо читаются из прежних схем; схема 5 хранит правила по ID системы и рецепта. Контракт, исходы pass/fail и ID градаций, поведение копирования и ограничения: [этап 8](docs/stage-8-recipe-rules.md).

Правило мира «Переносить свойства через эссенции» находится в «Настройки → Настройки мира → SkyBricate» и по умолчанию выключено. В этом режиме используется штатный крафт Fabricate, включая алхимию: связи свойств SkyBricate с эссенциями, их макросы, источники ActiveEffects и включённое поведение Fabricate не требуются. SkyBricate не добавляет макросы или эффекты, аудит применения и автоматическое открытие знаний; явно назначенные штатные эссенции, макросы рецепта, броски, расход и объединение стеков продолжают работать по правилам Fabricate. Каталог, назначения, знания и правила рецептов сохраняются и доступны; заслуженные ранее открытия знаний продолжают доставляться.

Включение правила возвращает проверку связей и поведения до расхода и применение свойств через эссенции, описанные ниже. Например, предмет без ActiveEffects подходит, если у связанной эссенции есть рабочий макрос; без обоих действий подходящее свойство блокирует крафт только при включённом переносе. Сила и лимиты свойств применяются в этом режиме. Переключение действует для новых попыток без перезагрузки; одна попытка алхимии или свёрнутая цепочка использует режим на момент её начала. Активный отложенный, многошаговый или progressive запуск продолжается только в исходном режиме, включая после перезагрузки: при несовпадении попытка отклоняется до нового расхода. Для завершения верните прежнюю настройку либо отмените запуск штатными средствами Fabricate. Старые запуски с контекстом SkyBricate считаются запущенными с переносом, штатные без него — без переноса; данные и уже потраченные ингредиенты не преобразуются при переключении.

В этапе 9а штатный крафт получает собственный снимок состава до расхода и единственный результат проверки Fabricate. GM связывает свойство с эссенцией текущей системы в каталоге; схема 6 сохраняет связь отдельно от native назначений и совместимо читает схемы 2–5. Для подходящих свойств проверяются связь, макросы/источники эффектов и лимиты; ошибки конфигурации останавливают попытку до броска, неизвестный фактический исход — до расхода. Этап 9а реализовал immediate single-step крафт, включая алхимию и extras; поддержка delayed/multistep/progressive добавлена в этапе 9в ниже. Этап 9б использует снимок выбранных свойств и источников для применения к результату; автооткрытие остаётся следующим этапом. Контракт и автоматические проверки: [этап 9а](docs/stage-9a-craft-adapter.md); stock probe: node tools/check-fabricate-craft.mjs.

В этапе 9б immediate single-step крафт применяет выбранные свойства через связанные essence macros и ActiveEffects. В правилах сохранённого рецепта GM отдельно задаёт силу каждого свойства по исходу проверки; без проверки сила всегда 1 независимо от количества ингредиентов. Независимые штатные эссенции сохраняются вне лимита SkyBricate, result macro остаётся последним writer. Схема 7 совместимо читает схемы 2–6. Каждый eligible результат сохраняет собственный аудит только реально оставшихся изменений и эффектов; такие результаты выдаются отдельно от стеков. Знания автоматически не раскрываются. Порядок, консервативная атрибуция, ошибки и ограничения: [этап 9б](docs/stage-9b-craft-application.md).

В этапе 9в отложенный шаг сохраняет происхождение компонентов до штатного расхода: после ожидания и перезагрузки используются сохранённые componentId, UUID и количества, даже если исходные Item удалены. Многошаговые рецепты, включая свёрнутые цепочки и смешанные временные шаги, применяют свойства отдельно к каждому реально выданному Item по расходу и проверке его шага. Предыдущие расходы не объединяются с последующими; переход без выдачи не считается применением. Проверка, время ожидания, отмена и расход остаются штатными. Progressive использует штатный бюджет выдачи, силу 1 и не допускает лимит по именованному исходу. Повреждённые, устаревшие и старые запуски без provenance останавливаются до нового расхода; знания автоматически не раскрываются. Контракт и проверки: [этап 9в](docs/stage-9c-craft-runs.md).

Изучена только версия Fabricate 1.9.10. Редактор использует полный штатный world setting fabricate.craftingSystems через адаптер только для чтения, проверяет его регистрацию и структуру. Запись в настройки Fabricate и изменение стороннего модуля не используются. Адаптер 9а оборачивает методы engine для получения штатного состава и проверки. Другая версия или неизвестный формат блокируют назначения; справочник по-прежнему использует проверенный контракт вкладки Fabricate. Обычная установка Fabricate достаточна; отдельная сборка и патч не требуются.

Справочник проверен с настоящими stock Svelte-компонентами TagsCategoriesView/VocabularyPanel. Назначения проверены в тестовом DOM и через оригинальные manager/repository Fabricate: одиночное/массовое удаление, отмена, отказ записи, повторная сверка после закрытия, изоляция систем. ApplicationV2 проверен по доступному контракту жизненного цикла и тестовой базе. Целевые версии Foundry VTT — 13–14; запуск в настоящем мире, перезапуск Foundry, темы, узкая ширина и реальные диалоги не проверялись.

## Сборка для разработки

Требуется Node.js 22 или новее. Для тестов выполните npm ci: happy-dom и Svelte используются только при разработке, устанавливаемый модуль внешних зависимостей не имеет. Команда npm run build создаёт dist/skybricate.zip и dist/module.json. Архив воспроизводим: содержит только явный список runtime-файлов с фиксированными ZIP timestamps. Документы, .reference, тесты, node_modules и служебные файлы в него не попадают. Проверка: node --test tests/regression.test.mjs.

Для установки выполните сборку или получите проверенный локальный dist/skybricate.zip, затем распакуйте его непосредственно в Data/modules/skybricate при остановленном сервере: module.json должен находиться в корне этой папки. Сохраните резервную копию мира перед обновлением. Используйте обычный Fabricate 1.9.10; после запуска включите оба модуля в настройках нужного мира. Если ранее был установлен экспериментальный патч Fabricate, переустановите официальный модуль той же версии с сохранением данных мира; назначения SkyBricate находятся в собственном setting и не требуют переноса.

Дополнительные адресные проверки: node --conditions=browser tools/check-fabricate-editor.mjs <путь-к-Fabricate> и node --conditions=browser tools/check-fabricate-assignments.mjs <путь-к-Fabricate>. Нужен Git checkout Fabricate с HEAD 5bf36ddf950619317e41737acd3bfa1305591a26 (по умолчанию .reference/fabricate). Probes читают исходники напрямую из этого коммита, создают временные тестовые файлы в кеше SkyBricate и не изменяют Fabricate. Сборка стороннего модуля не выполняется. Проверки не запускают Foundry.

Актуальный контракт и результаты: [отдельный редактор этапа 4](docs/stage-4-standalone-assignments.md). Предыдущие документы [реализации с патчем](docs/stage-4-assignments-implementation.md) и [контракта этапа 4](docs/stage-4-scoped-properties-contract.md) описывают исторический вариант и заменены новой передачей в части интеграции назначений. Их записи о трудозатратах, включая фактические 12,87 млн токенов прошлой задачи, сохранены.

Поля `manifest` и `download` подготовлены для GitHub Releases репозитория gorohovDM/SkyBricate. Адрес манифеста постоянный, адрес архива привязан к версии. Для будущего выпуска нужно обновить версию и адрес архива, собрать пакет и разместить оба файла в соответствующем релизе. Этап 11 создаёт проверенные локальные файлы поставки; GitHub Release и тег не опубликованы, доступность адресов обновления не подтверждена. Используйте локальную установку, описанную выше.

Справочник свойств показывает компактную горизонтальную форму названия, описания и связи с эссенцией; на узкой ширине поля переносятся. Рядом с вкладкой отображается количество свойств текущей системы, а в карточке — число уникальных сохранённых компонентов с обычным или особым назначением. Удалённые компоненты и другие системы в счётчик не входят; обновления назначений и каталога сохраняют вводимый черновик. Кнопка «Открыть знания персонажей» рядом с назначениями открывает окно ручного раскрытия свойств для GM. Перед крафтом связанное свойство требует активную эссенцию и включённое поведение: рабочий script-макрос при включённых эссенциях/макросах свойств либо источник ActiveEffects при включённом переносе эффектов в системе и рецепте. Подсказка в форме и отдельные сообщения GM поясняют отсутствие связи, макроса, источника эффектов или поведения; игрок получает общий отказ без скрытых названий. Проверки конфигурации продолжают останавливать попытку до расхода.
