# SkyBricate
Дополнение для Fabricate: скрытые свойства категорий ингредиентов, особые свойства компонентов и постепенное открытие знаний персонажами. Планируется использование штатных проверок, переноса эффектов и создания результатов Fabricate.

Текущая версия 0.2.0 содержит каркас, слой хранения данных, справочник свойств отдельно для каждой системы крафта и назначения свойств компонентам. В мастерском редакторе Fabricate выберите систему, откройте «Теги и категории» → «Свойства SkyBricate». Вкладка оформлена по аналогии с соседними справочниками: описание, поля названия и описания с кнопкой «Добавить», количество свойств и карточки со стандартной иконкой тега, названием, редактированием и удалением. Поиск пока отключён с пояснением; использование свойств пока не рассчитывается. Выбора иконок нет. Вкладка доступна мастеру при любом режиме выбранной системы; свойства пока не применяются при крафте.

Переименование сохраняет ID и связи. Удаление требует отдельного подтверждения и очищает назначения категориям, компонентам и порядок правил только в выбранной системе. Вкладка показывает ожидание сохранения, подтверждает успех после записи и сохраняет ввод при ошибке для повторной попытки. Панели справочника в настройках крафта больше нет.

Данные сохраняются в собственном скрытом world setting, схема 2. Изменять их может мастер. Каталоги, назначения категориям/компонентам и правила изолированы по системе. Старые тестовые данные схемы 1 с общим справочником не мигрируются: вкладка предлагает явный сброс с отдельным подтверждением удаления всех старых свойств, назначений и правил SkyBricate в мире. Сбрасывается только skybricate.data; данные Fabricate не меняются. Повреждённые, неизвестные и будущие схемы отклоняются без перезаписи и не получают кнопку сброса.

В редакторе отдельного компонента рядом со штатными тегами расположен блок «Свойства SkyBricate». Плашки «Свойства компонента» переключают его собственные свойства из справочника текущей системы. Кнопка «Сохранить свойства» сохраняет назначения отдельно; штатные поля сохраняйте кнопкой Fabricate. Снятие всех плашек сохраняет пустое назначение. При пустом справочнике показана подсказка, где создать свойства. Переименование и смена категории сохраняют назначения по ID; назначения категориям не подмешиваются. При ошибке записи выбор сохраняется для повторной попытки. Несохранённый выбор сбрасывается при смене компонента, системы, вкладки, закрытии и перечитывании; пояснение видно в блоке заранее.

После подтверждённого сохранения удаления компонента SkyBricate очищает его назначения только в соответствующей системе. При ошибке очистки мастер получает уведомление о рассинхронизации. Кнопка «Сверить сохранённые назначения» в мастерском редакторе повторно сравнивает назначения текущей системы с полным сохранённым списком компонентов Fabricate; она также помогает после пропущенного уведомления или перезапуска. Ошибка чтения или временно пустой список интерфейса не служат основанием для очистки. Два хранилища не образуют атомарную транзакцию.

Интерфейс назначений категориям и правил, знания персонажей, применение правил к крафту и раскрытие свойств пока не реализованы. При одновременной записи разных клиентов мастера действует правило последней записи; отдельной межклиентской блокировки нет. Кнопки перечитывания обновляют данные другого мастера и сбрасывают несохранённый выбор.

Изучена только версия Fabricate 1.9.10. Для назначений требуется собственная сборка с патчем `fabricate-component-assignments-v1`: обычная 1.9.10 сохраняет доступность справочника, но назначения блокируются с пояснением. Контракт даёт точные ID формы и уведомление подтверждённого удаления; эвристики по имени и внутреннее состояние Svelte не используются. Обновление обычной сборкой Fabricate может убрать патч и безопасно отключит назначения. Сопровождение этой сборки остаётся эксплуатационным риском.

Монтаж проверен с настоящими Svelte-компонентами TagsCategoriesView/VocabularyPanel и CraftingSystemManagerRoot/ComponentEditView в тестовом DOM: штатные вкладки/формы, одинаковые по полям компоненты, сохранение категории, отменённый и принятый переход с черновиком тегов, повторный монтаж и закрытие. Проверены реальные пути одиночного/массового удаления, общая запись репозитория, отказ сохранения и восстановление очистки. Целевые версии Foundry VTT — 13–14; запуск в настоящем мире, перезапуск Foundry, темы, узкая ширина и реальные диалоги не проверялись. При другой версии Fabricate или отсутствии необходимых API модуль отключается и сообщает мастеру причину. Неизвестная структура редактора блокирует соответствующий интерфейс и запись.

## Сборка для разработки

Требуется Node.js 22 или новее. Для тестов выполните `npm ci`: happy-dom и Svelte используются только при разработке, устанавливаемый модуль внешних зависимостей не имеет. Команда `npm run build` создаёт `dist/skybricate.zip` и `dist/module.json`. Архив воспроизводим: содержит только явный список runtime-файлов с фиксированными ZIP timestamps. `/docs`, `.reference`, тесты, node_modules и служебные файлы в него не попадают. Проверки: `node --test tests/regression.test.mjs`.

Для собственной сборки клонируйте `https://github.com/mistersilver-uk/fabricate.git` в отдельную папку, переключитесь на SHA `5bf36ddf950619317e41737acd3bfa1305591a26` и выполните в ней `npm ci --ignore-scripts`. Из SkyBricate запустите `node tools/build-fabricate.mjs <путь-к-копии-Fabricate>`: скрипт проверяет базовый SHA, применяет отслеживаемый патч, проверяет SHA256 исходников, выполняет штатную сборку и создаёт `dist/fabricate-1.9.10-skybricate-assignments-v1.zip` с SHA256. Повторный запуск поддерживается. Поставку обеспечивают файлы `patches/` и скрипт, локальная `.reference` не требуется.

Для установки распакуйте этот архив в `Data/modules/fabricate`, а `dist/skybricate.zip` — в `Data/modules/skybricate` при остановленном сервере. Перезапустите Foundry и активируйте оба модуля. Архив Fabricate содержит исходную лицензию и `SKYBRICATE-PATCH.json` с идентификатором сборки. Патч не публикуется во внешний upstream; релиз в main не создаётся.

Дополнительные адресные проверки: `node --conditions=browser tools/check-fabricate-editor.mjs <путь-к-Fabricate>` и `node --conditions=browser tools/check-fabricate-assignments.mjs <путь-к-Fabricate>`. Они требуют базовый SHA выше с поставленным патчем (по умолчанию `.reference/fabricate`) и не входят в обычные регрессионные тесты. Проверки не запускают Foundry. Подробный контракт и результаты: [передача этапа 4](docs/stage-4-assignments-implementation.md).

Поля `manifest` и `download` подготовлены для GitHub Releases репозитория gorohovDM/SkyBricate. Адрес манифеста постоянный, адрес архива привязан к версии. Для будущего выпуска нужно обновить версию и адрес архива, собрать пакет и разместить оба файла в соответствующем релизе. На этапе каркаса релиз и тег не публикуются; доступность адресов обновления не подтверждена.
